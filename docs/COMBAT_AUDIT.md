# 战斗机制、反馈与音效审计

日期：2026-10-16。审计基线：`d708b663d93ba92aabf844c61f0a2bed7e584e87`。
范围：现有多人飞盘玩法；原始 FF01 资产不变。以下区分代码事实、优化建议和实际验证，不把源码检查视为主观试玩或试听。

展示更新（2026-10-17）：排行榜和账号卡以已记录的“胜场”取代胜率指数展示，账户及回合数据不重置；确认的爆头提示和击杀信息显示服务器提供的飞行距离。

## 本次实现

后续策略更新（2026-10-16，用户明确要求）：所有账号的展示指数从 100% 重新起算。`winrate-loss-only-v1` 一次性备份旧 losses 并将该展示计数设为 0；wins/rounds 和其他统计保持不变。每场明确落败后指数乘以 0.95，胜局和平局不改变指数。迁移在 Durable Object 同步事务内执行并由 meta 标记防止重复。该值不是统计学上的胜场比例，实际胜负记录仍单独保存。

### 胜率算法资料与产品选择

- FIDE 的 Elo 规则把对手等级差换成预期得分概率，再与实得分比较；它用胜、负、和的结果估计相对等级，不符合“胜利不动、失败才下降”的产品规则。[FIDE Rating Regulations](https://www.fide.com/docs/regulations/FIDE%20Rating%20Regulations%202022.pdf)
- TrueSkill 用贝叶斯推断表示技能均值与不确定度，并根据观察到的比赛结果更新技能信念；它同样是相对技能估计，不是将每位新玩家固定显示为 100%。[Microsoft Research: TrueSkill](https://www.microsoft.com/en-us/research/project/trueskill-ranking-system/)
- 本项目因此使用明确的 loss-only 展示指数 `100 × 0.95^L`（`L` 为新基线后的明确输局数）。例如 0/1/2 次输局分别为 100.0% / 95.0% / 90.3%。赢家与平局不改变它。排行榜按淘汰数、再按输局数排序；它不声称预测真实胜率或玩家技能。

- 全服累计排行榜：淘汰数、胜场；个人账号卡同步展示累计胜场和已结算局数。局内小榜改用 `kills`，Tab 表格修正误写成“击中”的淘汰数标题。
- 服务器结算真实胜负和输局指数；客户端只格式化。累计淘汰优先排序，同淘汰按新基线后输局较少者优先。
- SQLite 增量添加 `wins`、`rounds`，保留账号、密码哈希、会话和历史战绩。历史没有回合结果，不能回填；无记录显示“—”，已参与但未赢显示 `0.0%`。
- 参赛账号按局去重，掉线重连不重复计数。中途离开者在该局正常结算时计入，入夜后新来的纯观众不计；下一局会计入。无人获胜的正常结束计局数但不计胜场；空房中止局不计。运行中的局及参与名单仍是现有内存状态，Worker 重启导致的中止局也不计。
- 普通、金色和狙击飞盘命中头部均立即淘汰满血玩家；身体仍扣 1 点生命（满血 2 点）。保留出生保护、单飞盘只能结算一次、复活和夜间出局规则。普通爆头增加明确的攻击方/受击方文字。
- 共用 `ROUND.blackoutSecondsLeft = 240`：客户端灯光、保安和服务器夜间规则统一在剩余 4:00 启动；最后 1 分钟决战时间不变。

## 现有机制与优化优先级

| 优先级 | 源码证据 / 问题 | 建议与验收方向 |
| --- | --- | --- |
| P1 | `server/room.ts::hit` 只检查投掷记录、时效、保护、距离；接触点允许离目标中心 3.5 m，没有服务器墙体遮挡或轨迹复核。爆头仅取上报高度相对当前目标中心是否大于 0.45 m。 | 下一阶段优先做服务端命中复核和有限历史姿态回溯；覆盖隔墙、伪造高接触点、延迟和高速移动。客户端目前会碰墙，但不能当作反作弊保证。 |
| P1 | `src/gameplay/discs.ts::update` 先用帧间线段检测胶囊，却把本帧末位置作为命中点；按目标遍历顺序选中第一个相交对象。 | 返回最早相交点与参数，按飞行路径最近目标结算；用真实接触点判头部。低帧率/高速飞盘可能出现头身误判，需几何与浏览器复现，当前未量化。 |
| P1 | `src/gameplay/match.ts` 在 `net.hit` 前立刻显示 hitmarker；服务器拒绝时没有纠正事件。 | 区分预测接触与确认命中，只有 `struck` 触发正式标记、音效和计数。测出生保护、无效上报和网络延迟。 |
| P1 | `Room.throw/hit` 未统一限制 round phase；结算间歇仍可投掷/更新淘汰数据。 | 为战斗入口加明确的阶段条件，同时允许合理的已发射飞盘交换击杀；覆盖回合边界，避免误伤投掷后死亡的正常判定。 |
| P2 | `match.ts` 对普通击杀调用 `hitConfirm`，狙击/金盘改走 `snipeConfirm`；只有前者播放 `kill.mp3`。 | 一个基础淘汰确认，叠加爆头/金盘差异层，避免专属路径跳过用户指定音频。现状不是所有击杀都播放 kill.mp3。 |
| P2 | `sound.ts` 有投掷、弹跳、命中、受伤、复活等合成声音及两个 MP3；弹跳不区分材质，远端声音只固定在事件发生点。 | 区分地板/墙/玻璃/身体，给 3–5 个轻量变体；增加近距离飞盘掠过声。玻璃当前是阻挡物，不应播放暗示已破碎的声音。 |
| P2 | `sound.ts` master 固定 0.55；`settings.ts` 只有鼠标灵敏度和视角。声音没有并发上限、混音总线/峰值保护。 | 总音量、战斗提示音音量、静音；限制同类声部并轻微压低环境层，避免多人击杀/公告淹没命中提示。是否实际削波尚未测量。 |
| P2 | `loadClip` 请求/解码失败会静默回退，未检查 HTTP 状态；音频节点未显式 `onended` 清理，没有统一 dispose。 | 加载状态可诊断，回退保持可玩；结束时断开节点、卸载时清理监听和 AudioContext。不能仅凭这点宣称已发生内存泄漏。 |
| P2 | 受击有方向弧、相机抖动/抬头、击退、血量；击杀有全服广播/连杀、粒子/FOV punch。 | 保留已有信息层级；增加低动态效果选项，限制高频全服公告。声音以短、清楚、可区分为目标，强烈摇镜不代替命中可信度。 |
| P2 | `Room.spotted` 增加局内死亡但没有持久化账号 deaths；结算赢家文字在客户端一律写“守住金飞盘”。 | 对齐保安淘汰统计；赢家文案区分最后幸存与持盘获胜。与本次胜率新增无关，保留为后续修复项。 |

## 战斗音效候选

后续用户已提供 Kenney Impact Sounds ZIP。130 个文件的技术审计、12 个候选及选择理由见 [Kenney 素材审计](audio-audit/README.md)，可在 [试听页](audio-audit/index.html)逐个比较。本次候选未接入游戏，主观试听与实战听感仍待确认。

现有文件用 macOS `afinfo` 检查：`kill.mp3` 为 48 kHz 双声道，估计 0.864 s；`defeat.mp3` 为 44.1 kHz 双声道，估计 4.598 s。白天复活仅 2.5 s，代码会在复活时淡出 defeat；试听时需要检查结尾是否自然。以上是文件元数据，不是实听评价。

已查阅官方素材页及许可说明；没有购买、整包下载、试听打分或替换现有 `kill.mp3` / `defeat.mp3`。这里的适配是制作建议，不是实听质量结论。

推荐路线：先试听 **Kenney Impact + Sonniss 破风/掠过**，配保留的简短电子确认；需要更鲜明的金盘身份时再选 BOOM。没有理由先买大型枪声包。

建议制作清单（目标时长，不是已制作资产）：

- 普通投掷 3 个变体，约 120–250 ms，自然破风，位置化；开镜飞盘用更紧的高频尾音。
- 身体命中 3 个变体，约 60–140 ms，柔和冲击叠短 click；爆头 2 个变体，约 100–200 ms，更清晰的瞬态。
- 淘汰确认约 250–450 ms，独立居中；爆头身份层不遮盖基础确认。保留用户提供的提示音前先比较电平与时长。
- 墙/地/玻璃各 3 个短变体，按碰撞速度缩放；掠过约 150–350 ms，仅足够接近镜头时触发，每飞盘限一次。
- 原始母带和许可保存在制作区；游戏只发布使用到的衍生文件，记录来源、哈希和许可，不整包搬运。
