**Document version:** 1.0 · **2026-10-15**  
**Project:** [lloyd-c137/moonshot-csgo](https://github.com/lloyd-c137/moonshot-csgo)  
**Project state:** DESIGN APPROVED / M0.1–M0.4 IN PROGRESS (see README "Verification state"). This document is a development contract, not a completion report.  
**Audience:** Coding agents, gameplay developers, environment artists, reviewers.

## 1. Product brief

### Subsequent authorized multiplayer work

The original M0 scope below is historical. Multiplayer frisbee gameplay was subsequently implemented with owner authorization. The 2026-10-16 maintenance request adds recorded round win rates, lethal headshots for all discs and blackout at three minutes remaining. See [COMBAT_AUDIT.md](COMBAT_AUDIT.md) for implementation scope, remaining combat/audio issues and verification; this does not retroactively mark the exploration gates complete.

Transform the real-campus-derived FF-01 architectural GLB into a desktop-browser, first-person open-world *exploration slice* with high-quality movement, valid indoor collision, room recognition and restrained in-world UI.

**Player fantasy:** Arrive in Moonshot Academy, walk around an uninterrupted, 1:1-scale first-floor campus, discover distinct interiors and explore organically. No forced quest, administrative dashboard or loading a new page on entering a room.

**M0 non-goals:** combat, firearms, NPC dialogue, persistent online identity, multiplayer, photorealistic reconstruction, other floors, the outdoor campus, live occupancy/CO₂/temperature, and mobile as a tested platform.

**Long-term vision:** richer interiors and authored discoveries (M1/M2); optional multiplayer (M3). The available geometry covers FF-01 only; “open world” here means *seamless free roaming within the available first-floor model*, not an invented whole campus.

## 3. Decision record: engine and alternatives

**ADR-001 — PlayCanvas Engine + TypeScript + Vite.** Start from the official first-person starter generated by `create-playcanvas`. Browser-first and closer to a game than an administrative 3D map. Official physics and GLB container loading integrate with the game loop. Implement minimal HTML/CSS HUD. Use TS for application/gameplay logic.

Evaluated alternatives:
- Three.js / React Three Fiber + react-three-rapier + Ecctrl: viable and strong for React-integrated MAC data visualization, but requires more custom game orchestration and an FPS camera integration.
- Three.js official `games_fps.html`: excellent reference for FPS + octree + capsule, but demo rather than complete production architecture.
- Babylon.js: capable game engine; a plausible fallback, but switching mid-M0 would cost reimplementation.
- Godot: excellent editor-driven game workflow, but more friction for current browser-first TS architecture.

Revisit ADR only for evidenced blockers (unworkable imported colliders, unsupported target browser/physics, performance), with a documented spike and acceptance test. No engine shopping mid-implementation without evidence.

**ADR-002 — Single-player first.** No server for M0. Later multiplayer via Colyseus only after M0 and M1 acceptance.

**ADR-003 — Source vs game-authored asset separation.** Keep raw GLB and JSON immutable and hash-verified. All new gameplay doors, furnishings, invisible blockers, trigger volumes, storytelling props and materials reside in an override/derived layer annotated `GAMEPLAY_AUTHORED` with anchors to semantic room IDs. Changes to unverified boundary candidates annotated `SOURCE_UNVERIFIED`.

**ADR-004 — No real-time campus metadata.** Room metadata imported for offline local exploration only, reviewed for safe exposure. No live sensor API, real people, occupancy, activity feeds or privileged maps.

## 4. Target user experience

### Entry

1. Local/static web app loads; player sees a loading indicator and any asset/physics errors.
2. Clicking **Enter Campus** starts/resumes gameplay and requests mouse pointer lock. Never auto-lock on page load.
3. Player spawns in a **tested navigable place** selected via an explicit coordinate/config rather than guessed from the room label or model origin.
4. First-person camera, unobtrusive crosshair, movement hint and room-location label appear.
5. Player can explore all *accessible routes physically present in the source*; door geometry determines navigation, and unfinished regions must not be implied accessible.
6. Escape unlocks mouse. Pause/reset setting recovers from blocked/wedged/out-of-world player state.

### Controls (desktop M0)

- WASD: move relative to yaw
- Mouse: look; clamp pitch
- Shift: sprint; explicit speed tunables
- Space: jump while grounded
- Escape: exit pointer lock, clear input
- R (only when paused or bound safely): recover to validated spawn
- E: reserved for later interaction; display prompt only when an interactable exists
- Directional arrow input and mobile gestures are not M0 commitments.

**Initial tune candidates, not verified specs:** walking 3.5–4.5 m/s, sprint 5.5–7.0 m/s; capsule radius 0.3–0.38 m; capsule height 1.65–1.85 m; camera eye height ~1.6 m; player step/slope settings calibrated against stairs/stands and actual geometries.

### Room HUD

- Use `room.id`, `name` and `kind`. Show entrance/exit state without constant noisy notifications.
- Resolve player XZ against candidate polygons, with holes excluded. Ignore `hasRegion=false` in polygon containment; use only authored triggers where known.
- Handle region overlaps and near-boundary jitter deterministically: boundary epsilon, sticky/hysteresis grace, area/priority tie-breaker, bounded events.
- Do not treat metadata `access: unknown` as permission to enter real-world restricted rooms. Fictional gameplay routes must be reviewed.

## 6. Game/runtime architecture

### Startup state machine

`BOOT → LOAD_PHYSICS → LOAD_VISUAL_SCENE → BUILD_COLLISION → BUILD_ROOM_INDEX → VALIDATE_SPAWN → READY → PLAYING`; branch to `ERROR` for failures with retry/reload and descriptive errors. Player controller only enabled in PLAYING. On visibility/pointer loss: `PAUSED`.

Boot must await loading GLB and Ammo appropriately. Fail explicitly on missing WASM/physics scripts, failed model request, wrong asset version, invalid coordinate metadata, missing collider, or unsafe spawn.

### Scene integration

- Load `MAC_Campus_FF01.glb` using PlayCanvas container asset API. Preserve scale. In PlayCanvas check parent transform and geometry local transforms; don't assume all nodes have identity transform.
- Keep reference object names/IDs for selection, collider classification and semantic room lookup. If optimization changes names, generate explicit stable manifest mapping.
- Visual mesh grouping should support materials per structural surface, arena and added decorations.
- Disable decorative `FloorLines` and label anchors in normal first-person view unless they provide intentional styled feedback. Do not let thin `Rooms` meshes produce flicker or floor obstruction.
- A playable floor's surface is at Y=0; colliders must line up with walkable top geometry.
- Materials: minimal neutral architectural whitebox in M0, intentional lighting and shadows; M1 responsible for art.

### Collision design

| Source / authored element | Target physical representation |
| --- | --- |
| Floor slab | static plane/shape respecting actual bounds, never a huge plane allowing walking outside building |
| Walls | subdivided simplified static colliders or static concave triangle mesh |
| Glazing | solid thin static collider aligned to visible glass |
| Arena court | walkable static floor |
| Arena stand base | simplified static ramp/mesh; stair behavior explicitly reviewed |
| Seating | selective colliders where traversal demands it, not 572 individually simulated rigid bodies |
| Room visual patches | no collision |
| Floor door/stair/furniture/court lines | no collision |
| Label anchors | no collision |
| Game-authored interactive doors | separate entity with opening state; collider toggled/animated coherently |

Static triangle mesh must not be used as the physics shape for a **moving/dynamic** body. Keep broadphase and draw-call footprint measurable. Prefer simpler geometry when physically equivalent. No accidental door sealing with wall approximations.

A collider-build manifest must include source mesh ID, collision type, transform, validation notes, and any gameplay-authored overrides. Compare collider world bounds with GLB world bounds.

### Semantic regions

Data contract for runtime importer:
```ts
type CampusRoomsFile = {
  model: string;
  status: string;
  frame: { units: string; axes: { x: string; y: string; z: string } };
  rooms: CampusRoom[];
};
type CampusRoom = {
  id: string;
  name: string;
  kind: string;
  hasRegion: boolean;
  geometryStatus: string;
  labelX: number;
  labelZ: number;
  polygon?: { outer: [number, number][]; holes?: [number, number][][] };
};
```
Confirm actual `holes` property spelling in input before using; validate unknown fields and duplicates. For each position (x,z), point-in-polygon test against outer ring minus holes; use a spatial index only if a measured performance bottleneck requires it. Pure unit tests include concave geometry, holes, boundaries, 2D/3D orientation, overlapping candidates, 6 label-only locations, negative coordinates and rapid corridor transitions.

### Asset pipeline

1. Extract archive to a staging directory **outside** the deployable public root.
2. Check sha256 for GLB and JSON and confirm model/status; fail loudly on mismatch.
3. Inspect GLB tree, root transform and bounding boxes; compute geometry stats.
4. Review prohibited/sensitive metadata. Construct a curated `public/assets/campus/` subset. Original source archive must not be blindly committed.
5. Test unoptimized render/physics first for correctness.
6. Only after baseline profiles, optimize GLB with glTF-Transform (prune/dedup/optional geometry/texture steps) without destroying semantic nodes or winding. Detect importer incompatibility and revert.
7. Keep hash/provenance mapping in an asset manifest. Publishing decisions recorded separately.
8. Ensure all required assets have deterministic local paths and work with Vite production base path. Avoid unresolved absolute URLs and unconfigured CORS.

### Graphics performance

Targets are **budgets, not achieved numbers**:
- Desktop baseline: target 60 FPS on a defined mainstream laptop + Chrome; report hardware, resolution, browser, scene and P50/P95 frame time.
- Baseline first and optimize based on measured bottleneck: draw calls, frame time, collision cost, GPU memory/texture sizes, physics objects.
- No blanket post-processing, dynamic shadow casting for every object, or heavy volumetric effects in M0.
- Approximate GLB geometry is manageable, but draw calls and collider complexity matter more than raw filesize.
- Optimize GPU asset lifetime, material reuse and visibility/frustum control; avoid premature LOD infrastructure.

### M0.0 — Repo bootstrap and verified starter

Tasks:

2. Scaffold official `create-playcanvas` FPS starter in a throwaway directory; inspect generated scripts/license and copy needed implementation, docs, scripts and legal files.
3. Pin compatible npm versions, add lockfile, document Node/tooling versions, commands and architecture.
4. Wire TypeScript, lint, test runner, Vite and simple local developer page; browser smoke test of unchanged first-person demo.
5. Document physics runtime dependency and production asset locations.

PASS: fresh checkout + documented npm install/build/dev; pointer lock WASD look/jump demo works; production build loads with physics. Commit reproducible lockfile. Source-missing state must be explicit.

### M0.1 — FF01 model ingestion

Tasks: import verified GLB; preserve original scale, units and orientation; expose named source groups; loading/progress/errors; create asset manifest and a safe curated source-data import path.

PASS: GLB loads without axis/scale errors, entire model in camera bounds, 1m reference probe correct; no original archive implicitly served. Record GLB validation/integrity. If source not provisioned: `BLOCKED_ASSET`, **not PASS**.

### M0.2 — Collision, movement and safe route

Tasks: collision-only layer for actual structural walls/floor/glazing/arena; physics init; choose spawn after spatial checks; player collider/camera separation; walk/jump/sprint; set world bounds + recovery; doorway clearance test map, sample walk routes.

PASS: no clip through walls/glazing, no fall through floor, intended door openings traversable, stairs/stands tested, escape releases lock, recovery works. Test at least 3 actual door apertures, 2 area transitions, spawn-to-arena path. Record failures and geometry uncertainty rather than faking fixes.

### M0.3 — Rooms and locations

Tasks: validate data contract; geometric containment test with hole treatment and tie-breaking; build small HUD; enter/leave events and discovery once per location per session; label-only semantic fallback with honest uncertainty.

PASS: fixture tests for 159 polygon records and 6 label-only records; no false inside events from holes; HUD changes on crossing boundaries; no flooding from boundary jitter. All identifiers remain stable.

### M0.4 — Stabilization, profiling and preview

Tasks: add CI (typecheck, lint, unit, production build, asset presence preflight), browser smoke, accessibility/keyboard, pause/resume, console/error review, benchmark report and README.

PASS: CI green with full assets; production preview on clean install; documented manual play path; actual FPS/frame stats on tested hardware rather than unsupported claim. If benchmark hardware unavailable, mark NOT RUN.

### M1 — A living campus (post-M0)

Start by art-directing **one** verified accessible region (e.g. arena + adjacent corridor), not every room. Add modular architectural material family, realistic scale furniture, HDR/lighting, spatial audio, non-interactable animations and ambience. Use Poly Haven/Kenney/Quaternius assets only after per-asset provenance/licensing and privacy review.

PASS: polished route, stable perf, texture/material consistency, still no geometry breakage.

### M2 — Discoverable world (post-M1)

Config-driven interactables, readable environmental story fragments, visual/audio state on interaction, collectible discoveries, local-only versioned save, accessible key prompts and optional authored door system. Preserve non-linear exploration.

PASS: at least one complete discovery experience, reload persistence validated, no broken route/physics.

### M3 — Shared world (optional, after approval)

Evaluate Colyseus (or comparable authoritative server) for rooms, connections, avatar states, reconciliation and abuse protection. Define permissions, data retention, privacy and concurrency needs before implementation.

PASS: separately defined after a research spike. No commitment to deployment scale or server costs before measurements.

## 8. Test strategy

Automated:
- Asset manifest: exact input hashes, schema/IDs, coordinate frames, source status and model source availability.
- Geometry: polygon concavity, holes, negative quadrants, overlap decisions, missing polygons and near-wall positions.
- Collision: if possible scene probes/raycast snapshots, capsule-clearance results, bounds checks, spawn validity.
- Runtime: fresh load, pointer lock on click, Escape pause, keyboard input, missing-asset error path, recovery, room HUD event.
- Build: strict TypeScript, lint, unit tests, production bundle, local preview.
- Security: secrets check, no remote sensor API and no personal data in public assets.

Manual, mandatory for physics/feel:
- Walk spawn → first corridor → accessible room → arena → reset.
- Attempt to run into wall and glass; approach several entrances; jump on flat and arena edge.
- Minimize/restore tab during movement, press Escape, reload and resume.
- Check at least desktop Chrome; expand browsers on explicit acceptance.
- Capture screenshot/video and logs only after actually running the game.

Test recording template: `Test | Expected | Actual | PASS/FAIL/BLOCKED/NOT RUN | Commit | Hardware/browser | Evidence`.

## 9. Risks and controls

| Risk | Impact | Mitigation |
| --- | --- | --- |
| Unverified 2D-derived geometry | Wall/opening mismatch | Preserve confidence statuses; collider QA; separate overrides |
| No volumetric doors/furniture | World feels bare | M1 asset pipeline; no fake “verified” additions |
| Long/thin architectural wall meshes | Physics snagging/performance | Simplified static collision and doorway clearance sweep |
| PlayCanvas physics asset errors in Vite | Player falls/no collision | explicit initialization gate + prod preview test |
| Large/complex GLB scene hierarchy | Draw calls, profiler noise | measured optimization; preserve semantic mapping |
| 6 label-only spaces | Location gaps | trigger candidates with authored status; unknown fallback |
| Restricted real campus information | Inadvertent disclosure | reviewed derivative assets; private repository; no public auto-deploy |
| Tool/library dependency churn | Broken builds | pin lockfile, read upstream examples, release notes |
| “M0 done” declared after build only | Non-playable demo | mandatory browser physics tests and recorded QA |
